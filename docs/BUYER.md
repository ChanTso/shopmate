# 买家购物工作台

买家页面位于 `http://127.0.0.1:3100/buyer`，商家页面仍为 `/`。两端使用同一个 ShopMate API 和 Next 应用，登录状态在浏览器内存中分开保存。本文描述操作与业务边界，不是一次真实模型验收通过记录。

## 登录与会话

先按 [README](../README.md#本地运行) 启动本地服务。统一夹具提供两个演示买家：

| 账号 | 本地生成密码文件 |
| --- | --- |
| `shopmate-retail-buyer` | `.run/buyer_1_password` |
| `shopmate-retail-buyer-2` | `.run/buyer_2_password` |

密码只在本机读取，不复制进提交、截图或执行记录。商家操作员账号没有买家权限，进入另一个页面不会授予另一角色。刷新页面后重新登录，从会话列表恢复；会话绑定原主体和角色，不能通过页面选择其他用户。

普通购物 API 只需买家登录身份，不要求创建聊天。聊天使用独立 conversation ID；助手正在生成时可以继续普通购物，只有真实版本冲突或未知命令尚未处理时需要先核对。

## 购物、结账与退款

- **选商品**：商品页每页 24 个目录根，打开系列查看全部真实规格组合。可以直接选择 SKU 加车，也可以让助手推荐、比较、规划清单、解释政策和查询订单。缺货或暂停的商品显示暂不可购买。
- **改购物车**：数量按钮、移除和 Agent 工具都调用真实 Java 购物车。金额、库存、可售性与版本读回后展示，不把聊天快照作为当前库存。
- **确认订单**：点击“核对并确认结账”，读取当前报价，核对商品、规格、数量和商品支付合计，勾选确认后创建订单。提交的是 Java 原始整数金额、SKU 版本和购物车版本；版本冲突后必须重新读取并确认，不自动接受新价格。
- **确认模拟付款**：创建订单不等于已经付款。结账记录中的付款按钮是独立确认；部分付款时，继续操作只处理原结账记录内未付款的子单。不会从付款成功推断已发货。
- **确认退款**：本人订单页或助手先准备一份固定订单、金额和有效期的退款申请。核对保存的申请后，勾选并点击“确认提交退款申请”。模型没有确认接口；`REQUESTED` 是已受理申请，不代表退款到账。

订单展示历史下单金额、实际付款状态、各退款状态和独立履约记录。没有履约观察时明确显示“暂无履约记录”，不根据预计送达时间自动推进状态。

## 配送估算与商品付款

结账页的“查询当前整车配送估算”按真实 SKU 数量、当前商品快照、账户会员与服务配置查询，显示估算时间、币种、配送费用和日期。

配送仅供咨询：页面没有购买或收取配送服务，估算费用不加入商品付款。商品支付合计只对应实际子订单，不能将其描述成已购买的含运费订单。

## 停止、恢复与未知写入

“停止生成”会中断本次流式连接；关闭页面也会取消当前 fetch。它们不会撤销已经保存的购物车、订单、付款或退款申请。停止后点击“恢复会话”读取服务端状态，不根据未完成的回复判断写入是否发生。

若写入可能已提交但没有收到回包，页面显示原操作、请求身份和待确认状态。恢复只查询原回执，**不会自动再次加车或下单**。核对后点击“继续原操作（同一请求）”，才复用保存的原 body 和 key 重试；原操作属于同一买家的另一个会话时，也可从当前命令列表恢复；服务端保留它的原授权绑定。未知购物车写入未处理前，新的购物车写入暂不可用。

浏览器仍存有首次请求而服务器暂时读不到记录时，同样保留原 key，不生成新的请求冒充重试。刷新后以服务端持久命令恢复。付款中断后先读回结账记录，再明确继续原未付款子单；退款确认重复调用回放原回执。

## 资料与记忆

资料页读取真实账户偏好、会员和常用地点，模型不能修改这些资料。对话记忆另存于服务端，按经过认证的角色和主体隔离：两个买家彼此分开，同一主体的商家和买家记忆也分开。

点击右上角账户头像查看、纠正或忘记单条买家记忆；资料页勾选明确确认后可清除当前买家身份的全部记忆。清除不删除订单、购物车或账户资料。后台提取沿宿主的撤销代次处理，已撤销的旧提取结果不能覆盖清除操作。读取失败会显示错误，不伪装成没有记忆。

六类生成式卡片和会话记录仍有原代码版本边界。历史商家分数不是买家成绩；新版浏览器与真实模型验收另行记录，不以 TypeScript 检查或请求执行结束代替业务成功。
