# ShopMate 工作台

复用 `vendor/commerce-agents/examples/retail/merchant-web`、`storefront-web` 与 `examples/web-shared` 的 Next、PortalShell、聊天流和卡片交互。许可证和原始版权声明保留在 vendor 及复制文件中。

```sh
cd web
npm ci
npm run typecheck
npm test
npm run build
SHOPMATE_API_URL=http://127.0.0.1:8101 npm run dev
```

访问 `http://127.0.0.1:3100`。商家页面位于 `/`，买家页面位于 `/buyer`，入口互相可见。浏览器请求同源 `/api/merchant` 或 `/api/buyer`；Next 根据 `SHOPMATE_API_URL` 转发至 Python host。生产构建时也要设置此变量，因为 rewrites 在构建时确定。

登录使用 CityBuddy Auth 操作员账号。Bearer 只保留在页面内存，刷新需重新登录，然后恢复已持久化会话。会话 ID 随 `X-Session-Id` 发送。草案批准/取消直接调用 host 操作端点；聊天文字不能批准变更。运行中的会话禁止新的聊天和审批，刷新会话可恢复已保存结果。

`web-shared` 是 `file:` 依赖；`.npmrc` 的 `install-links=true` 将其作为本地包复制安装，避免源目录无法解析 React。修改 vendor UI 后重新执行 `npm ci`，确保检查和运行使用最新代码。页面宽度可以保存于 localStorage，身份令牌不写入浏览器存储。

商家页面包含经营概览、分页目录和规格详情、库存健康、订单问题、营销计划/已批准促销、分页草案历史。目录、库存和经营图表标明报告窗口，操作日期使用真实 Shanghai 时间。营销预算是本地计划，支出与归因收入保持各自观察来源；未知收入不呈现为零或 ROAS=0。促销批准会修改实际价格，窗口结束后不会自动恢复。

`public/products/` 复用 vendored retail 的现有图片及 `IMAGE-CREDITS.md`，未新增远程素材或另一个站点。图片为空的商品使用组件缺省展示。买家与商家共用一个 Next 应用，使用独立的 API singleton 和登录状态。

HTTP 读取错误显式显示，不替换成空列表；401 清除内存登录，业务 409 保留分类（如未来促销仍待批准），仅实际会话繁忙显示等待提示。审批期间禁止新的聊天、审批和会话切换，“停止生成”中断当前 fetch，服务端继续沿现有断连清理保存状态；停止不撤销已经提交的结果，之后可刷新会话恢复。


买家保留商品、比较、规划、指南、订单状态、结账六类生成式卡片，另有服务端保存的退款确认卡。24 个目录根一页，系列详情展示全部实际规格组合；购物车的数量、可售状态和金额以 Java 读取为准。推荐卡片中的展示价格不参与正式提交的报价：确认结账提交 Java 原始整数金额、SKU 版本与购物车版本，报价改变必须重新确认。

结账创建订单、模拟付款、退款申请确认分别使用明确按钮。付款结果与履约事实分别展示，REQUESTED 不表示已到账。整车配送估算按实际数量读取，标明币种和观察时间，不进入商品支付合计，也不代表已选择或购买配送。

写入请求在首次发送前生成稳定 request key；浏览器断连保留原请求，服务端恢复只读取原回执。未知状态显示原操作，用户明确继续才复用同一请求；切回原会话前不能重试。刷新页面后仍以服务端保存的命令恢复，凭证和交易请求不写入 localStorage。

买家账号面板读取实际记忆，支持纠正与单条忘记；资料页提供明确确认的全部清除。资料、记忆和工具权限按登录身份与会话角色由 host 校验，页面不能选择其他主体。商家运行记录展示实际身份的经营记忆；读取失败会显式提示。

测试覆盖整数报价、原 key/body 重试、角色令牌隔离、内存读取失败、真实 fetch 中止及既有商家行为。命令通过记录与业务模型验收由项目根目录另行记录，此说明不声称新的真实模型成绩。

外部搜索结果使用双端共用的 `web_sources` 卡片：摘要按纯文本显示，编号只对应服务实际返回的 citation 元数据；查阅来源另列，不声称包含全部网页。链接仅允许无用户凭证的绝对 HTTP(S) URL；摘要里的任意网址不会自动成为来源。没有引用时明确提示仍需核对，不补造链接。

回合结束时，记忆提取不可用或因用户修改/清除而撤销，会在该条回复下提示，刷新恢复后仍可看到。这个提示不会把已经完成的业务回复或已经提交的操作标成撤销；记忆面板继续显示实际保存的事实。


商家首页使用同一份 overview 展示成交指标、三类待办和全店近期订单；订单与售后页复用这一读取结果。六个指标均可预填具名追问，四项日趋势按上海报告窗口对齐；缺数值日期留空断线，当前操作订单不受历史报表截止限制。近期订单逐 SKU 子单展示整数分历史金额，付款、履约和各退款状态分别显示；页面不执行商家发货或发送买家消息。

搜索卡的长摘要默认折叠，实际引用链接始终独立可见；摘要按纯文本显示。买家导航在窄屏内横向滚动，保留全部入口。
